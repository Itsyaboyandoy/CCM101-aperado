# 🏛️ Laboratory 10 – The Enterprise Cloud Architect

**Mission:** The Enterprise Cloud Architect

**Project Name:** CloudNova

**Project Type:** Private Cloud Infrastructure and Containerized Web Application Deployment

## 📌 Project Overview

**CloudNova** is a cloud infrastructure project developed for CCM101 – Cloud Computing. It demonstrates how to build, manage, and secure a web application using a virtual machine and Docker.

The project uses Ubuntu Server to run two connected services: WordPress and MariaDB. WordPress handles the website, while MariaDB stores its data.

The system also includes firewall protection, secure remote access, permanent data storage, and automatic database backups.

## 🎯 Project Objectives

- Set up a Linux server using Oracle VirtualBox.
- Configure network connections between the laptop and the virtual machine.
- Install Docker and Docker Compose.
- Deploy WordPress and MariaDB as connected services.
- Set up storage to keep application and database data safe.
- Protect the server using firewall rules and secure SSH access.
- Create a Bash script for automatic database backups.
- Schedule backups using Cron.
- Document the setup and maintenance procedures.

## 🏗️ CloudNova Infrastructure Architecture

CloudNova uses a virtualized server environment to host and manage a containerized web application.

The infrastructure integrates the host computer, virtualization platform, Ubuntu Server, firewall controls, Docker services, persistent storage, and automated backups.

### Infrastructure Components

| Component | Responsibility |
|---|---|
| Windows 11 Host | Provides the workstation used to manage the server. |
| Oracle VirtualBox | Runs the Ubuntu Server virtual machine. |
| Ubuntu Server | Hosts Docker and server management services. |
| NAT Network | Provides internet connectivity to the virtual machine. |
| Host-only Network | Connects the Windows host and Ubuntu Server. |
| UFW and iptables | Controls network access and firewall rules. |
| Docker Engine | Runs the application containers. |
| Docker Compose | Defines and manages the containerized services. |
| WordPress | Provides the web application. |
| MariaDB | Stores the website's database records. |
| Docker Volumes | Maintains application and database information. |
| Bash and Cron | Supports scheduled database backup operations. |

## 🌐 Network Configuration

CloudNova uses two virtual network interfaces.

The NAT network provides internet access for the Ubuntu virtual machine, while the Host-only network allows direct communication between the Windows host and Ubuntu Server.

| Network Interface | IP Address | Purpose |
|---|---|---|
| NAT (`enp0s3`) | `10.0.2.15/24` | Internet access |
| Host-only (`enp0s8`) | `192.168.56.103/24` | Windows-to-server connection |
| Windows Host-only Adapter | `192.168.56.1` | Host access to Ubuntu |
| WordPress Application | `192.168.56.103:8080` | Website access |

### 🌍 WordPress Website

`http://192.168.56.103:8080`

This address allows the Windows host to access the WordPress website through the Host-only network.

## 🐳 Docker Services

The application consists of two connected Docker containers.

| Container | Docker Image | Purpose |
|---|---|---|
| `cloudnova-wordpress` | `wordpress:latest` | Hosts the WordPress website. |
| `cloudnova-database` | `mariadb:11.4` | Stores WordPress database records. |

The containers communicate using the dedicated Docker network named `cloudnova-network`.

### 💾 Persistent Storage

CloudNova uses Docker volumes to maintain important information independently of the container lifecycle.

| Volume | Purpose |
|---|---|
| `wordpress_data` | Stores WordPress files and uploaded content. |
| `mariadb_data` | Stores MariaDB database information. |

The MariaDB database port is not directly published to the host network.

Persistent storage helps ensure that application data remains available even when containers are restarted or recreated.

## 🔒 Security Configurations

The CloudNova infrastructure includes several measures designed to reduce unauthorized access and limit unnecessary network exposure.

### Implemented Security Features

- UFW enabled with a default-deny incoming policy.
- Outgoing traffic permitted.
- SSH access restricted to the Host-only network.
- SSH password authentication disabled.
- Direct root login through SSH disabled.
- ED25519 SSH public-key authentication enabled.
- Docker firewall rules configured to restrict website access.
- MariaDB accessible through the internal Docker network.
- Database credentials stored in a protected `.env` file.
- Sensitive environment files excluded from the public repository.

### Security Concepts Applied

| Security Concept | Description |
|---|---|
| Default Deny | Blocks incoming connections unless explicitly permitted. |
| Principle of Least Privilege | Grants only the permissions required for an operation. |
| SSH Key Authentication | Uses cryptographic keys to support secure remote access. |
| Network Isolation | Separates internal database communication from external access. |
| Credential Protection | Keeps database passwords out of published source files. |
| Port Management | Limits exposure to necessary network services. |

### Important Docker Security Consideration

Docker-published ports may not follow ordinary UFW filtering in the same way as non-containerized services.

For this reason, CloudNova uses additional Docker-related firewall controls to restrict access to the application.

## ⚙️ Automated Database Backup

CloudNova implements a Bash-based database backup system to support maintenance and data recovery.

The backup script is designed to generate compressed MariaDB database backups and manage stored backup files automatically.

### Backup Configuration

| Setting | Value |
|---|---|
| Script | `automation-script.sh` |
| Backup Directory | `/opt/cloudnova/backups/` |
| Scheduling Tool | Cron |
| Backup Frequency | Daily |
| Scheduled Time | 2:00 AM UTC |
| Philippine Time | 10:00 AM |
| Retention Period | Seven days |

### Backup Operations

The automation script performs the following tasks:

1. Creates a database backup from MariaDB.
2. Compresses the backup using Gzip.
3. Adds a timestamp to the backup filename.
4. Performs backup file validity checks.
5. Removes backups older than seven days.
6. Records backup results in a log file.

# 🔄 Virtual Machines vs. Containers

Virtual Machines and containers are both used to run applications in isolated environments, but they use different approaches.

| Category | Virtual Machines | Containers |
|---|---|---|
| Architecture | Runs a complete guest operating system. | Shares the host operating system kernel. |
| Startup | Generally requires more startup time. | Usually starts more quickly. |
| Resource Usage | Typically uses more resources. | Generally more lightweight. |
| Isolation | Provides virtual machine isolation. | Provides process and application isolation. |
| Portability | Depends on compatible virtualization platforms. | Uses portable container images. |
| Deployment | Requires guest OS installation and configuration. | Applications are deployed using container images. |
| Common Tool | Oracle VirtualBox | Docker |

## 💡 Summary

Virtual Machines are useful when a complete operating system environment is needed.

Containers are useful for packaging applications and their dependencies into smaller, more portable environments.

CloudNova demonstrates how these technologies can work together by running Docker containers inside an Ubuntu Server virtual machine.
