# Mission Reflection

In this laboratory activity, I acted as a cloud data engineer for a client who needs to store millions of user-uploaded photos. Object storage is better suited for this than a traditional block storage hard drive. Block storage works well for a single server's operating system or database, but it does not scale easily. Object storage keeps each photo as an object with its own metadata and unique ID, grows almost without limit, and can be accessed over the web. Since containers are temporary, the photos also need to live in a storage service outside the web server container.

Docker made deploying MinIO much easier. Instead of installing and configuring everything manually, I ran one `docker run` command that downloaded the image, mapped ports 9000 and 9001, and set the admin login through environment variables. It also taught me to troubleshoot: the original `minio/minio` image failed with a "pull access denied" error, so I researched the cause and switched to a mirror image while keeping the rest of the command the same. A bucket is a container that organizes objects in cloud storage, similar to a top-level folder. I created a bucket named `client-photos` in the MinIO web console and uploaded a sample file to prove the system works.

Large companies protect object storage data from server crashes by keeping multiple copies of each object across different drives, servers, and even locations. Replication and backups let the system recover files and stay available when one machine fails, which matters for a service holding millions of customer photos.

My confidence with the Linux command line is growing. I became more comfortable running Docker commands, checking containers with `docker ps`, and testing the server with a `curl` health check. Some commands were confusing at first, but reading error messages and fixing them helped me understand what each part does. I still need more practice, but this lab gave me hands-on experience I can use in future cloud projects.
